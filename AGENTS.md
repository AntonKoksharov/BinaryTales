Правила и ограничения разработки бэкенда (FinSmart)

1. Стек технологий
Язык и фреймворк: Python 3.10+, FastAPI (асинхронный).
Валидация: Pydantic v2.
База данных: SQLite (для локальной разработки) с обязательной совместимостью с PostgreSQL (SQLAlchemy 2.0 Async / Alembic).
Документация: OpenAPI / Swagger (автогенерация через FastAPI).

2. Поведение агента и стиль кода
Комментарии: Писать комментарии в коде ТОЛЬКО для неочевидной, сложной или нетривиальной бизнес-логики. Не писать очевидные комментарии вида # роут для получения пользователей или # импорт библиотек.
Никаких заглушек: Запрещено оставлять # TODO: реализовать позже, pass в бизнес-логике или # ... остальной код без изменений. Код функций и эндпоинтов выдавать целиком в рабочем виде.
Точечные правки: Не переписывать файл целиком, если требуется изменить несколько строк или одну функцию. Беречь существующий рабочий код.
Зависимости: Не добавлять сторонние pip-библиотеки без прямого согласования.

3. Стандарты FastAPI и роутинга
Асинхронность: Все эндпоинты объявлять через async def. Не использовать блокирующие синхронные вызовы (например, time.sleep, синхронные запросы requests) внутри асинхронных роутов.
Структура API: Роуты обязательно группировать через APIRouter с префиксами и тегами (например, prefix="/api/v1/transactions", tags=["Transactions"]).
Swagger / OpenAPI:
У каждого эндпоинта указывать понятные summary, status_code и response_model.
Использовать description в docstring эндпоинта, если логика требует пояснения в Swagger.

4. Схемы Pydantic
Разделение схем: Строго разделять модели для создания, обновления и ответа (например: TransactionCreate, TransactionUpdate, TransactionResponse).
Связка с ORM: В схемах ответа обязательно указывать конфигурацию model_config = ConfigDict(from_attributes=True).
Строгая типизация: Использовать актуальные типы (int, str, Decimal для денег, datetime, UUID при необходимости). Никаких Any без крайней необходимости.

5. Работа с базой данных (SQLite / PostgreSQL)
Совместимость: Не использовать специфичные для SQLite функции или типы, которые сломаются при переходе на PostgreSQL (использовать абстракции SQLAlchemy).
Деньги и балансы: Для финансовых сумм в базе и схемах использовать Numeric / Decimal (никогда не хранить деньги во float).
Сессии: Работать с базой только через генераторы сессий и Depends (Dependency Injection: db: AsyncSession = Depends(get_db)). Не открывать сессии вручную внутри функций логики.

6. Обработка ошибок
Все предсказуемые ошибки отдавать через HTTPException со стандартными кодами (400, 401, 403, 404, 409, 422) и понятным текстом в поле detail.
Не глушить ошибки «тихими» except: pass — логировать или пробрасывать корректный HTTP-ответ.
